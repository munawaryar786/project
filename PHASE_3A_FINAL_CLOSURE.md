D. Passenger logout result

Passenger logout revokes stored PassengerSession rows, clears canonical session/CSRF cookies, clears legacy passenger cookies, and leaves driver/admin cookies untouched. /api/passenger/me no longer authenticates. Isolated tests pass.

E. Token replay/revocation behavior

Canonical driver/admin tokens are stateless: logout clears browser cookies only. A stolen token remains usable until expiry unless the actor authVersion changes or the actor becomes inactive. Driver/admin canonical tokens are checked for expiry, actor, version, role and server-side active state. jti is signed and required but is not persisted or blacklisted.

Passenger canonical tokens also require a live PassengerSession row, matching sid/jti hash, expiry and non-revocation. Passenger logout and password reset revoke PassengerSession rows. Legacy passenger sessions are checked against their stored session row and are cleared during logout.

This closure keeps the intended model: secure HttpOnly cookie + bounded lifetime + authVersion/active-state invalidation, with PassengerSession revocation where the architecture already supports it.

F. Password reset/change authVersion behavior

Password reset now increments Passenger.authVersion and revokes all PassengerSession rows before issuing the replacement session. Authenticated profile password completion also increments authVersion, revokes existing sessions, and issues a replacement canonical session. Existing-account password creation in the legacy setup path increments authVersion.

No driver/admin self-service password-change endpoint exists. Inactive driver/admin/passenger checks remain server-side.
